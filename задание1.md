# Вводная и контекст
**Компания:** QuantumForge Software (HQ — Хельсинки, R&D — Таллин). 9 лет на рынке. Флагман — SaaS «Digital Twin», клиенты: ABB, Wärtsilä, скандинавские энергокомпании. Помимо core‑продукта — консалтинг (~20% оборота).

**Цель внедрения RAG‑бота:** сократить время поиска и коммуникации, повысить продуктивность, автоматизировать ответы на FAQ, выявлять пробелы в документации, улучшать качество знаний, масштабироваться на другие команды и соответствовать требованиям аудитов (SOC 2).

**Исходные данные (источники знаний):**
- ~18 000 Markdown/MDX в репозиториях.
- ~3 000 страниц Confluence (30 пространств).
- ~250 PDF‑спецификаций.
- Прирост: ~400 стр./мес.
- Артефакты: GitHub Wiki/README, ADR, CODEOWNERS, dbt‑доки, ER‑диаграммы, Zendesk Guide, Google Docs.

**Проблемы сейчас:**
- Разрозненность и дубли, несогласованность версий между Confluence/Notion/PDF.
- Долгий поиск (новые инженеры тратят до 4 ч/нед). Повторяющиеся вопросы.
- Нет единых владельцев страниц → устаревание за 2–3 месяца после major‑релизов.
- SOC 2 yearly review отнимает ~140 часов ручной сверки.

# Подход к решению (высокоуровневый дизайн)
1. **Ингест и нормализация:** коннекторы к GitHub, Confluence, Google Drive, Zendesk. Чистка, дедупликация, извлечение метаданных (владельцы/CODEOWNERS, версия, коммит).
2. **Индексация:** чанкование, эмбеддинги, векторный индекс + BM25.
3. **Ретраивер:** dense + keyword + фильтры метаданных, reranker.
4. **Генерация:** промпты по ролям, цитирование, ссылки на источник.
5. **Feedback‑петля:** логирование, оценка ответов, генерация тикетов о пробелах.
6. **Говернанс:** контроль чувствительных данных, RBAC, аудит, lifecycle‑политики.

# 1. Сравнение LLM (локальные vs облачные)

| Критерий | Локальные (Hugging Face, self-host) | Облачные (OpenAI / YandexGPT) |
|---------|-------------------------------------|-------------------------------|
| **Качество** | Хорошее с RAG; топ‑модели Llama/Mistral/Qwen | Отличное, сильный reasoning, меньше галлюцинаций |
| **Скорость** | Зависит от GPU, на CPU медленно | Быстро, эластичное масштабирование |
| **Стоимость** | Покупка/аренда GPU, DevOps | Плата за токены, дешевле при низкой нагрузке |
| **Развёртывание** | Сложнее | Очень просто |
| **Безопасность** | Полный контроль над данными | Требуется no‑training + EU‑регион |

**Вывод:** лучший вариант — **гибрид** (облачный LLM + локальные данные/индексы).

---

# 2. Сравнение моделей эмбеддингов

| Критерий | Локальные Sentence‑Transformers | Облачные OpenAI Embeddings |
|---------|--------------------------------|-----------------------------|
| **Скорость индексации** | Высокая на GPU | Высокая, но сетевые лимиты |
| **Качество** | SOTA‑качество (bge/e5/mxbai) | Очень высокое |
| **Стоимость** | Дёшево при больших объёмах | Дорого при массовых переиндексах |
| **Приватность** | Полный контроль | Текст уходит в облако |

**Вывод:** для QuantumForge оптимально — **локальные эмбеддинги на GPU**.

---

# 3. Сравнение ChromaDB и FAISS

| Критерий | ChromaDB | FAISS |
|---------|----------|--------|
| **Скорость** | Высокая (HNSW, встроенная оптимизация) | Максимальная производительность |
| **Метаданные/фильтры** | Есть встроенно | Нет — требуется обвязка |
| **Персистентность** | Встроенная | Требует кастомной реализации |
| **Удобство** | Очень простая эксплуатация | Требует инженерных усилий |
| **Стоимость владения** | Минимальная | Нужно строить инфраструктуру вокруг |

**Вывод:** **ChromaDB** — лучший выбор для пилота и дальнейшего роста.

# 5. Архитектурные варианты

### **A. Гибрид (рекомендуемый)**
- Облачный LLM
- Локальные эмбеддинги
- ChromaDB  
**Плюсы:** быстро, безопасно, дешево, масштабируемо.

### **B. Полностью локальный**
- Self‑host Llama/Mistral  
- FAISS  
**Плюсы:** максимальная приватность.

### **C. Облачный‑first**
- Всё в managed‑сервисах  
**Минусы:** риски данных, высокая стоимость.

### **D. Гибрид + мульти‑регион**
- Для будущего продуктирования.

**Итоговый рейтинг:** A ⭐⭐⭐⭐ → B ⭐⭐⭐ → D ⭐⭐ → C ⭐

---

# 6. Почему ChromaDB — окончательный выбор
- Персистентность и удобные коллекции  
- Богатые фильтры по метаданным  
- Прямые интеграции с LangChain  
- Простота эксплуатации в DevOps‑среде  
- Достаточная скорость на объёмах QuantumForge  

FAISS стоит рассматривать только при переходе к 100M+ векторов и жёстких SLA.

---

# 7. Практическая настройка индекса

- Чанки: 700–1000 токенов, overlap 100–150  
- Метаданные: source, service, codeowner, version, soc2_id, space  
- Ретраивер: hybrid BM25 + dense  
- Reranker: cross‑encoder локально  
- Инкрементальная индексация через webhooks  

---

# 8. Безопасность и соответствие (SOC 2)

- Detectors + masking для PII и секретов  
- EU‑residency данных  
- RBAC + SSO  
- Логи запросов, ретеншн, аудит цепочки документации  

---

# 9. Итоговые рекомендации
1. Использовать архитектуру **Вариант A** — гибрид.  
2. Эмбеддинги — локальные (Sentence‑Transformers).  
3. Векторная база — **ChromaDB**.  
4. LLM — облачный (OpenAI/YandexGPT) в режиме no‑training.  
5. Запустить feedback‑петлю и автоматизацию обнаружения пробелов.

# Итог
**Выбор векторной БД → ChromaDB.**  
Причины: фильтры, персистентность, гибкость, интеграции, низкая стоимость владения.
